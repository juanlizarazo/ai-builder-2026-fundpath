Security

Last updated August 2026

FundPath handles company and funding data, so we build with security as a default, not an afterthought. Here's what's actually in place.

Per-user data isolation

Every record in Firestore and Storage is scoped to the signed-in user who owns it. Firestore and Storage security rules enforce this at the database layer — a user can only read or write their own profile, funding path, and uploaded documents. Shared reference data (grant program listings) is read-only from the client and can only be written by trusted backend services.

Authenticated, validated backend

Every Cloud Function that touches your data requires a verified sign-in token before it runs. Inputs are validated against an expected schema before processing, and sensitive actions (like sending notifications) are rate-limited per user to prevent abuse.

OWASP-aligned security headers

The app is served with HTTP Strict Transport Security, a Content-Security-Policy that restricts what scripts and origins can run, X-Frame-Options: DENY to block clickjacking, X-Content-Type-Options: nosniff, and a strict referrer policy — headers recommended by the OWASP Secure Headers Project.

Encryption

All traffic to and from FundPath is encrypted in transit over HTTPS/TLS. Data at rest in Firestore and Cloud Storage is encrypted by default.
